# Runtime dependencies for RynnWorld-Latent (Cosmos3-Edge) + bundled RynnLAM.
#
# Authoritative source is pyproject.toml (`pip install -e .`); this file mirrors
# [project.dependencies] for `pip install -r requirements.txt` workflows. Keep the
# two in sync.
#
# NOTE: this project builds ON TOP OF NVIDIA's cosmos-framework, which is VENDORED
# under third_party/cosmos-framework (code only) and is NOT on PyPI. Put it on
# PYTHONPATH instead of installing it (scripts/train.sh does this for you):
#   export PYTHONPATH="$PWD:$PWD/third_party/cosmos-framework"
# Model weights are not bundled either -- see scripts/setup/download_weights.sh.
#
# The list below is the VERIFIED import closure of the vendored cosmos-framework
# (config load + video-SFT dataloader + training loop + inference) plus RynnLAM.
# cosmos-framework is a large framework whose import graph reaches further than a
# typical video model, so this is longer than the RynnWorld-Latent layer alone --
# every entry here is imported at load time by code on the edge path. Packages
# that pip pulls transitively (portalocker<-iopath, botocore<-boto3,
# braceexpand<-webdataset, docstring-parser/typeguard<-tyro, click/protobuf<-wandb,
# pyarrow/dill/multiprocess/fsspec/xxhash<-datasets, ...) are intentionally NOT
# listed. NVIDIA-image-only, non-PyPI, or optional pieces are documented at the
# bottom instead of pinned here.

# --- core: RynnWorld-Latent + RynnLAM -------------------------------------
# torch 2.7 is the floor: the base->DCP converter (convert_edge_to_dcp.py, run by
# scripts/setup/download_weights.sh) imports torch.distributed.checkpoint.hf_storage,
# native only in >=2.7 (the torch_dcp_hf_backfill shim is NVIDIA-image-only, not on
# PyPI). torch 2.11+ hits a torch._dynamo UserError (data-dependent guard) inside the
# cosmos forward; 2.10 is the verified line (all cluster training runs on it).
# torchvision floor tracks torch (2.7<->0.22 ... 2.10<->0.25).
torch>=2.7.0,<2.11
torchvision>=0.22.0,<0.26
numpy>=1.24.0,<2
opencv-python>=4.8.0
av>=15.0.0,<16.0.0
einops
hydra-core
omegaconf

cattrs

pydantic
safetensors
imageio
imageio-ffmpeg    # imageio's mp4 writer (rollout video export) needs the ffmpeg
                  # plugin; without it imageio falls back to PyAV, whose write()
                  # rejects the `quality` kwarg cosmos passes
# transformers 5.x refactored qwen3_vl.video_processing (drops get_image_size),
# which the vendored cosmos reasoner/VLM processors import. The 4.57 line is the
# verified-working one; <5 also keeps huggingface_hub on the 0.x API cosmos uses.

# NOTE: tqdm and huggingface_hub are intentionally NOT declared as direct
# dependencies (third-party SCA compliance). Both are pulled in transitively by
# transformers / datasets, and the vendored code loads tqdm dynamically with a
# no-op fallback (see NOTICE). transformers<5 keeps huggingface_hub on the 0.x
# API cosmos uses, so no explicit pin is needed here.

                    # transient_retry import boto3/botocore unconditionally under
                    # COSMOS_TRAINING, which defaults on). RynnWorld-Latent's OWN

                    # SKU is `local` (object store disabled), and
                    # enable_gcs_patch_in_boto3=False, so no S3/GCS API is ever
                    # called. It cannot be dropped without patching the vendored
                    # subtree, which NOTICE keeps as close to upstream as possible
                    # ("Vendored subtree vs. upstream"). Installed, imported, never exercised.

#   pip install -e ".[serve]"           # cosmos ray-based inference serving

#                  Only to read the non-file video sources RynnLAM's FrameReader

#                  Plain mp4/webm needs nothing beyond `av`. zarr and numcodecs
#                  must be a matched PAIR (see pyproject.toml for why).
#   serve:         ray -- cosmos_framework.inference.ray serving only; not needed
#                  for training or scripts/inference/rollout.py.

#   lerobot               -- train.py installs an inert stub (RynnWorld does not
